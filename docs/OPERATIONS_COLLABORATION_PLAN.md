# 运营协作与性能修复

先实现并验收用户明确要求的卡顿修复、多人观看、单操作员、运营与聊天快速切换；完成后按用户选择进行 antislop 审查。保留既有苹果视觉与字体，不另起全站改版。

## 已测基线

- 小红书容器CPU约145%，限额150%；浏览器renderer累计约103%，GPU进程约29%，x11vnc约6%。主要负载不是主站网关。
- 主机约16GB内存，可用约1.6GB。
- 运营组件按workspace条件挂载，切离即卸载iframe。
- 当前VNC入口为独占模式，第二个会话只能被拒绝。

## 实现

1. 每个平台一个操作员租约，其他连接默认观察员。观察连接使用服务端强制view-only VNC端口，不仅是前端禁用鼠标。
2. 角色抢占必须原操作员主动退出，断线超时后释放。两个窗口即使使用同一运营密码，也各有独立clientId。
3. WebSocket广播角色与人数，不依赖刷新。只允许经过运营认证的客户端进入。
4. iframe首次进入才加载，切离隐藏保留。隐藏时结束高带宽画面传输、保留内存快照和轻量状态连接；回去恢复画面，不整页刷新。
5. 聊天同样按需保留实例，隐藏时不轮询、不标已读、没有漂浮层泄漏；保留草稿与位置。两处有直接往返入口。
6. 远程画面默认1280×800（比1440×900少约21%像素）、流畅编码；提供清晰档。禁掉远程浏览器非必要动画，不强制冻结后台上传或发布工作。

## 视觉映射

| Before | After | Why |
| --- | --- | --- |
| 切换离开即销毁iframe | 保留挂载、隐藏时停画面流 | 避免重复认证与整页重连 |
| 独占“连接浏览器” | 观察员／操作员两态分段控件 | 直接对应用户协作角色 |
| 重连需要重载整个iframe | 显式恢复连接消息 | 保留当前平台、素材草稿 |
| 无直接聊天往返 | 运营页消息按钮、聊天页运营按钮 | 高频切换不再绕工作台 |

风格：苹果系统字体、原有中性底色和蓝色操作态，控制条而非额外信息卡。按钮至少44px，频繁切页无阻塞转场，保留即时按压反馈。业务状态只显示角色、观看人数和真实连接状态。
