## 工程标准审查

- 商品偏好仍用现有 `ManualReview` 游标同步，不新增第二套轮询或平行状态。
- 发现反馈与商品变更、协作日志在同一事务中持久化。撤销使用原始前后快照与条件更新，避免覆盖后来操作；归档、下架、已购买商品不回卡。
- 库存创建使用数据库去重；库存和销售写入采用原子快照校验与最多三次重试。销售/调整记录只在成功取得写入权后追加。
- 机会计算与依赖读取在同一事务内锁定证据；数据库另有当前证据写入守卫。
- 新增两份前向迁移，不改写已执行迁移；旧错误证据只降级，不删除商品、购买记录或审计值。
- 来源名称和成本展示使用共享函数，普通卡与发现卡遵守同样口径。未知邮费标下限，竞拍单价标当前值；不恢复评分、匹配度或置信度 UI。

## UI 取舍

沿用现有 Apple 式浅色玻璃视觉，ENERGY 1 / RHYTHM 2 / MOTION 2。本轮只补真实数据与交互缺口，不重新设计外部 agent 已完成的页面。

- 来源显示实际平台/域名，而非抓取引擎。
- 价格、数量、单价沿现有优先级；未知数据不伪装成确定金额。
- 库存分页沿用现有按钮与字体，点击区域至少 44px，不改变商品卡高度。
- 发现三卡预载保留，堆叠、减少动效与底栏遮挡需通过实际截图复核。

## 明确边界，不宣称已解决

1. **真实账号权限尚未实施。** 原任务明确先做管理员/员工演示，后续再接真实账号。当前仍是共享采购站点；购买凭证和写接口不能视为已受登录隔离保护。向陌生公众长期开放前需要单独确定访问控制方案。
2. **AI 的全量实时能力不等于配置成功。** 当前运行时识别 11 个 Provider，成本、额度、商业使用和数据门禁仍会限制可用候选。本轮不擅自放宽门禁或产生付费探针。
3. **真实闲鱼覆盖率需独立实测。** 解析、匹配、失败处理和持久化测试通过，不代表登录/配额/平台限制消失；不声称已抓全市场。
4. **不要将持续变化的工作区当作已冻结发布快照。** 最终发布前与仍活动的两个项目任务协调收口，新增改动须重新验证并进入对应镜像。
5. **旧迁移校验和另有两项既存漂移。** `20260830020000_seller_source_data`、`20260901070000_listing_type_unknown` 的本地文件 hash 与数据库历史记录不同，也不是简单 CRLF/LF 差异。本轮未篡改数据库历史值；迁移状态与实际升级验证已通过，但在恢复这两份精确历史文件前不宣称全仓迁移历史零漂移。

## 比价运行审计闭环

`ChinaMarketComparisonRun` 的 started、ready/insufficient、failed 已接入 worker。租约获取与启动记录同事务，代表样本/汇总/run 完成同事务。失败只终结自身 token，已完成 run 不被后续入队错误改写；固定分类错误不存原始响应、凭据或地址。该目录 114 项定向回归通过。
