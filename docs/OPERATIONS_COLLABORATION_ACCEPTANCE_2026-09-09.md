# 运营台协作与流畅切换验收

## 本轮需求结果

| 需求 | 结果 |
| --- | --- |
| 运行卡顿 | 减少传输像素、降低默认JPEG质量及编码CPU、禁用Xvfb中的软件GPU渲染路径、减少远程非必要动画；离开运营台停止高带宽画面流，保留状态连接 |
| 两名管理者同时看 | 已实现。两个已认证会话同时连接，观察者可看到同一个浏览器 |
| 单操作员 | 已实现。整个运营台只有一个操作租约，前端两态开关，服务器原子互斥；观察端使用x11vnc强制只读5902通道 |
| 操作权交接 | 操作员切回观察员后另一人可取得操作权；写通道先关闭再允许交接。离开主站运营页暂留30秒，断开状态连接最多约20秒释放 |
| 运营与聊天往返 | 两处直接入口；运营iframe只首次进入创建，聊天实例按需保留。切换不整页重载，保留聊天草稿、平台及画面快照 |
| 隐藏页面的副作用 | 隐藏聊天停止轮询、不把新消息标已读、不渲染砍价浮层；隐藏运营台停止画面流，轻量WebSocket保留角色同步 |
| 手机输入bug | iframe焦点通过严格same-origin/source校验通知父页面；键盘出现时使用visualViewport真实高度/偏移，隐藏底栏并让登录表单在可见区域独立滚动；保持16px输入字号，不禁用缩放 |
| 追加手机体验 | 应用内展开/收起、不依赖iPhone全屏API；原大/适应画面与拖动/点击模式；独立输入辅助面板、Tab/回车/退格；省流/流畅/清晰三级JPEG质量 |
| 发布内置表单 | 新增发布辅助：识别官方页面的标题、正文、地点及其他可编辑文本；用户确认后仅填入改动字段。地点入口及候选项取自当前页面，不自动最终发布 |
| 文案粘贴拆分 | 发布辅助整段文案第一行作为标题，其余作为正文；保留正文段落。先预览，确认才写入，超长提示而不截短标题；手动修改后再次识别不会被待拆分草稿覆盖 |
| antislop时机 | 按用户要求，完成后统一审查，见 `anti-slop/audit-001-2026-09-09.md` |

## 性能实测与限制

修复前一次采样：小红书CPU145.14%，接近容器150%上限；主机可用内存约1.6GB。CPU统计包含多核，100%表示一个核。

优化后的空闲/低活动采样：小红书约9%至31%，抖音约60%至64%；远程画面从1440×900改为1280×800，像素减少约21%。采样时刻页面活动不同，不能作为严格同负载基准，也不能据此声称固定倍数提速。已确认两个平台还保留登录资料及可操作画面。

追加待机页后，无人观看稳定阶段采样：小红书0.16%、抖音0.17%。这是无人观看的省资源结果，不是操作中CPU或帧率承诺。原平台标签没有被关闭，返回时激活原标签而不是重新登录。

真正的网络延迟仍由当前电脑上行、访问者网络和临时Cloudflare隧道决定。没有声称达到本机原生视频编辑性能。画质提供省流/流畅/清晰切换；操作通道扫描等待25ms、观察通道40ms，这些是调度参数而非实际FPS承诺。慢连接排队超过2MB断开恢复，避免延迟帧越积越多。不冻结平台上传、发布、验证流程。现有素材分块上传在切去聊天后允许原已授权任务完成，观察员不能创建新上传。

## 未夸大的边界

- 没有iPhone真机控制权限，只完成手机宽度及visualViewport/焦点模拟；需用户实际Safari键盘复核。
- 此轮未实施上一轮尚未上线的完整登录助手前端、共享运营密码迁移、固定公网前置页。发布辅助不同于密码登录助手。这些不等于本轮“角色切换”：两位管理者保留各自现有运营认证，也可共同观看同一平台账号。
- 没有删除功能、清Cookie、发送测试聊天消息、提交平台登录/验证码或发布内容。
