# 进货计算器与玻璃视觉增强

## 范围与方向

Operate 模式：采购人员在移动网页中快速读价、核算客户报价与内部利润。
沿用现有白底黑线 Logo、系统字体、蓝色操作与低对比背景。项目视觉增强 revision 4；skill 的 ENERGY/RHYTHM/MOTION 仍为 3（其最高档），不虚构官方等级。
用户要求持续应用既有设计规范；antislop 在实施期间检查，明确要求的全站玻璃与动态背景优先于通用剂量建议。

## 组件与数据

- Dashboard → ProcurementCalculatorWorkspace（client）→ 输入分组、结果明细、客户报价复制。
- 纯 TypeScript 公式与验证放在 lib/procurement-calculator.ts，沿用附件计算方法，金额四舍五入到分；逆向采购上限以实际报价公式二分验证。
- 客户预计转售利润 = 国内整批售价 − 客户应付；内部收益 = 客户应付 − 实际商品成本 − 实际运税。
- 共享现有汇率只用于首次填入或用户手动同步；不会在用户修改后自动覆盖。表单 sessionStorage 按管理员隔离，离页保留，复制只包含客户视图。
- 沿用项目 React state，不引入第二套全局 store。没有 AI 调用、没有客户公开存储、没有数据库写入。
- Yahoo!フリマ当前标价 × 80%，日元向上取整。显示“最低降价20%测算”，不是卖家承诺，不替换真实价格和利润成本。

## 排版

- 手机商品卡价格整行、数量与单价第二行，不再三列挤压；金额不省略。窄于 360px 单列。固定高度改为统一最小高度、同排等高，放大文字和长金额可自然扩展，禁止裁切关键信息。
- 计算器手机先选择对外/对内，输入与结果纵向；桌面输入在左，报价/收益在右。各字段明确币种与整批/单件单位。
- 货币采用系统字体 tabular-nums；信息密度通过主次而非极小字号维持。

## 动效与材料

- 单一全局双层低对比光场，复用到各工作区；仅 transform/opacity 缓慢移动，页面不可见时暂停。
- 导航、工具栏、弹窗材质厚度加强；数据卡保留高不透明底保证价格可读。
- 按压反馈即时，面板进入从当前位置缩放与位移；尊重 reduced-motion、reduced-transparency 与高对比偏好。复用项目 motion，不增加动画依赖。

## 安全与验收

- 附件 HTML 仅提取公式，不执行/嵌入其脚本。React 文本转义；数字显式验证范围，0、空值、负数与无效数分别处理。
- 管理员选择不是权限认证，“对内”不是服务端保密边界。客户仅拿到显式复制的对外文本。
- 批量验收 320/390/430/1440px、极大价格、价格降幅、反算边界、亏损、空输入、公式展开、复制隔离、离页保留。
