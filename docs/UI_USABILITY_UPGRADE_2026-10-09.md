# 假面采购 · 视觉与操作升级

## 本轮范围

取消 Codex 每十分钟自动跟进；不停止商品抓取。保留所有业务入口、品牌资产和数据语义。
升级现有 Apple / Liquid Glass 界面，不将简约等同于平板白框或删除功能。

## 共享规则（cross-surface alignment）

- 内容：高不透明阅读面，图片、价格和标题优先。
- 操作层：玻璃工具栏、选中滑块、弹窗和浮层，利用真实背景形成空间层次。
- 页头：品牌/页面身份在左，语言和设置组合，个人入口独立；汇率不是按钮。
- 首页：完整保留趋势、交易分布、平台和分类，但手机使用紧凑横向数据行，避免两块空大的统计卡。
- 列表：按断点统一最低高度、同一网格等高；完整内容和大字体可共同增高，不再以最大高度裁切。常用操作保持固定位置，图片切换不触发详情。
- 导航：首页、AI、消息、工作台四个入口；一个持久选中滑块，手机全宽贴底。
- 动效：按压立即反馈；导航/菜单表现来源和去向；不延迟操作，不在每次数据刷新时重播。
- 可访问性：44px以上热区、可见焦点、原生按钮、reduced-motion/reduced-transparency退化。
- 治理：在现有最终样式层修正覆盖，不再追加新的全站覆盖层；图库和历史菜单使用局部模块隔离。

## Mobile checkpoint

平台：现有 React / Next.js 移动网页及添加到主屏幕的网页，iOS优先，兼容Android；不是迁移原生框架。
导航：保留4个底部主页面及现有子页面历史；不改业务状态缓存或联网写入。
离线：本轮不承诺离线商品交易；最近页面状态仍在本地，失败时保留已有内容。
已读：mobile-design及thinking、touch、performance、backend、testing、debugging、iOS/Android参考。
原则：触点稳定；信息层次清楚；只在交互发生时付出动效成本。
规避：不将桌面简单缩小；不对全页使用transform；不在长列表逐卡叠加blur。
MFRI：平台5+可访问准备5−交互2−性能2−离线依赖1=5，需统一性能与交互验证。

## 并行分工与验收

1. 主控：共享材质、页头、首页与主导航。
2. 图库：稳定热区、切换反馈、事件隔离、位置计数。
3. 历史：边缘停靠、长按移动、菜单层次、键盘与焦点。
4. 审查：实现后统一antislop与回归审查，随后测试/构建/浏览器验证。

验证需覆盖加载完成的真实数据、320/390/桌面宽度、底栏位置、切图、设置、历史跳转和减少动态；不可用模拟数据代替真实在售数据验收。无实体手机时明确保留实机验证限制。

此规则只管理共享表现与交互，商品抓取、AI池、分类和交易业务留在现有功能模块。

## 浏览器验收方式

当前运行的生产服务不热更。本轮在浏览器请求层载入已构建的HTML、JS、CSS和本地图标，GET数据仍来自真实运行服务；拦截所有写入，未发送聊天、修改收藏/备注、购买或触发AI请求。最终构建使用与Compose一致的`NEXT_PUBLIC_API_BASE_URL=/backend`。

这验证的是新构建的真实浏览器表现，不等于已部署。Docker管理管道无响应时保留原服务；不能用旧线上页面HTTP200代替新版发布成功证据。

初次统一验收确实捕获了`card action clipped`，随后针对高度合同修复。新增检查覆盖全页卡片金额/按钮边界、切图位置、备注打开前后尺寸、拍卖、设置居中、历史菜单及贴底导航。实体iPhone/Safari与桌面图标系统缓存仍需上线后实机检查。
