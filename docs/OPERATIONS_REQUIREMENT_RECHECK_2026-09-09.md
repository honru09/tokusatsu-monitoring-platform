# 运营台需求复核

范围：最近一轮运营台性能、两人协作、手机辅助操作、聊天往返、发布辅助、文案拆分。不是全历史项目需求已全部完结的声明。

## 本次新发现

1. **识别期间切换平台**：旧平台响应可覆盖新平台表单。已用公网UI的受控延迟响应复现，初次结果 `staleScanDiscarded=false`。
2. **填入过程中继续修改**：完成回调清除所有dirty标记，新修改误标已同步。已在相同UI测试复现，初次结果 `editDuringFillRetained=false`。
3. **缺少读回验证**：原流程发送DOM/输入指令后直接返回成功，无法发现框架把值改回或拒绝输入。已增加真实浏览器隔离编辑页对照：字段被平台逻辑回滚时必须返回未通过，不能假报成功。

## 修复约束

- 平台切换使旧编辑请求失效，旧响应不再更新当前平台界面。
- 每个平台保留独立草稿，确认中的新修改只在与实际发送值一致时清除dirty。
- 扫描完成时使用最新草稿而不是请求开始时的旧值。
- 实际DOM填入后核对标题/正文，全部匹配才返回verified；不匹配返回422并保留草稿，不自动重试或发布。
- 不替用户提交真实平台发布、验证码或付款，不发送测试聊天。

### 当前运行的证据

- Node运营/入口/守护：20项测试通过。
- Python控制器读回核对：成功与拒绝两种情况通过（1个测试覆盖2分支）。
- Playwright隔离编辑页：标题、富文本、地点入口、地点选项、敏感/隐藏字段排除、字段变化拒绝、读回一致、平台回滚不报成功通过。
- 公网UI竞态测试：两个原来false的断言现为true。
- 六尺寸移动测试同时核对iframe内部和父页面中的输入框位置，均通过。
- 运营容器已构建、部署，健康；用户平台浏览器资料未清除。

### 测试隔离说明

公网运营台实际显示“龙正在操作”。为不打断真实操作，本次前端竞态和尺寸复核使用隔离角色/表单响应，真实画面通道仍是服务端观察员连接，没有取得操作租约。不是声称在公网重新完成了所有真实操作权交接；互斥与交接逻辑由本次后台测试和上一轮公网验收共同覆盖。

### 仍不能宣称已全面验收的部分

1. iPhone物理键盘、系统密码自动填充和Safari工具条，需要真实设备使用反馈。
2. 小红书/抖音非标准自定义地点组件未逐种实测；识别不到时仍需远程页面手动操作，不猜坐标。
3. 未发送真实发布内容来做验收，因此不把通用字段填入测试称作所有平台完整发帖链路通过。
4. 上一轮之前的完整登录助手前端、共享运营密码迁移、固定公网前置入口仍是原有待办，不包含在这次最近一轮需求的完成声明里。
