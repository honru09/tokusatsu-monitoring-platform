# 全站简化与详情重做验收

## 本轮交付

- 商品详情：独立滚动、完整照片、价格主次、固定单行操作栏；描述预览/展开、原文切换、SHF/闲鱼/AI/平台明细/纠错入口保留。
- 纠错：默认收起，保留审计流程；补齐数量验证和保存失败恢复。
- 焦点：原生 disclosure summary 可达，Tab 不进入关闭的 details 表单。
- 系统：共用 Apple 系统字体、轻量玻璃、分组行与明确语义色；精简首页、工作台、AI助手/状态、卖家、设置、链接、物流和计算器的重复文案。
- 清理：仅删除被新版详情取代的旧样式规则，未删除业务数据和功能。

## 验收证据

- Web：32 个文件、158 项测试通过。
- 生产镜像：Next.js 编译、类型检查、页面生成及 Docker 构建通过。
- 批量浏览：17 个工作区各检查390与1440px，详情检查320/390/768/1440px。首次发现手机底栏两行，由旧CSS强制grid导致；冲突规则已移除。
- 完整购买数据加载后发现 implicit grid 最小内容宽度导致390px手机扩大到441px；已为购买包、商品行明确设置 min-width:0 与 minmax(0,1fr) 单列，长标题/备注可换行。复验29个真实购买包：320/390/430/1440px 的 clientWidth、scrollWidth、innerWidth 三者一致。
- 最终 Web 容器已部署，公网健康接口返回 ok / API 200。详情操作栏在4种宽度下保持单行。
- 原文切换、纠错默认关闭、失败保存可重试、Escape关闭，均有浏览器/自动化测试证据。
- 浏览器测试为模拟视口，不等同于实体 iPhone / Android 性能测试。
- 为防测试消耗AI额度或修改真实数据，详情翻译请求与保存请求在验收浏览器内返回模拟失败；商品读取为实际数据。
- 原始结果与截图：`.impeccable/review/refinement/acceptance.json`、`detail-<width>.png`、各工作区截图。
- 设计扫描：仅存在继承视觉体系的色阶/圆角建议，不宣称全代码零审查项。

页面加载、折叠、失败状态与图像比例均在本轮范围内；不扩展到抓取源可用性或AI模型性能审计。
