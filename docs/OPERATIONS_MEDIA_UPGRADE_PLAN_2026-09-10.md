# 运营台多图与 Liquid Glass 升级路线

范围：运营台素材上传、平台附件导入、工具栏/手机辅助面板。保留小红书/抖音官方页面、单操作员/多观察员、聊天往返、文案拆分及现有账号资料。用户已指定直接执行，统一验收后再做 antislop 审查。

## 现状与问题

- 系统file input已有multiple，但图片与视频混合accept，移动端可能进入不适合批量照片的选择器；UI只有一个总进度，没有逐张状态。
- 当前串行for循环放在一个try中，一张失败即停止剩余队列；上传期间不能追加选择；不能单张重试。
- 上传后的素材仅有下载链接，需要在远程文件选择器手动寻找，没有把一批素材送入平台上传控件的通道。
- 工具栏、角色条、辅助键、面板多层占用空间，手机关键操作拥挤。应让远程画面为主，素材与导入动作固定在可触及位置。

## 阶段与验收

### P0：数据与权限底线

- 不删现有素材、Cookie或数据库，不绕过平台验证。
- 未认证不能查看素材；观察员不能上传或操作平台附件。
- 不接受任意本机路径。导入只能取当前平台素材目录中的已完成文件。
- 图片写入平台附件控件不等于发布，绝不自动点击正式发布。

### P1：多图上传队列

- 图片和视频分别选择，图片明确image/* + multiple，不使用capture限制。
- 一次多选、重复追加、桌面拖放进入同一队列；每项独立进度/完成/失败/取消。
- 小并发（2路）分块传输，失败不阻断后面的文件；失败项手动重试；取消清理自己的未完成临时文件。
- 已完成的队列与素材可多选。显示真实选中数量，失败不计成功。
- 同名文件不覆盖，按后台生成唯一名称保存。

### P2：送入平台页面

- 先识别当前官方编辑页的file控件，展示其图片/视频类型及是否支持多选。
- 选中素材后点击“添加到页面”；服务器校验文件归属和控件快照，再通过浏览器文件输入协议设置整批路径。
- 多选控件批量传入；单文件控件不强改multiple、不伪造平台支持，明确提示切换图片批量上传区。
- 页面变化/多个不明确目标/类型冲突时停止，不猜坐标。服务器只报告控件已接收，不声称平台上传已完成。

### P3：统一界面与交互

- 视觉：系统字体、纸白#f5f5f7、墨色#1d1d1f、系统蓝#0071e3、辅文#58616e。沿用白底黑线logo。
- 玻璃限于工具层和浮动面板：高不透明内容底、细高光边、有限模糊与柔和投影，让素材缩略图与文案保持清晰。
- 远程画面是主区域；少量一级工具固定，键盘/画质等辅助操作按需展开，不删除现有功能。
- 手机素材为底部面板，独立滚动；固定面板主操作栏；桌面为右侧检查器。
- 主触摸目标≥44px，输入≥16px；减弱动态/透明度/高对比度设置有降级；动效不阻塞操作。
- 用户追加：内置上翻/下翻/顶部和页面缩放按钮。观察员仅操作本地画面适应/原大，改变远程页面滚动和大小需要操作员权限；不自动按发布或确认按钮。

### P4：集中验收与发布

- 单元/接口：一批多图、单张失败后继续、重试、取消、同名、路径穿越、观察员拒绝、目标变化拒绝。
- 隔离真实浏览器：multiple file控件一次收到多个文件；single控件拒绝多图；不触发发布按钮。
- UI：320/390/430px及桌面，照片追加与复选、面板关闭重开、错误反馈、Tab/Escape、减弱动效。
- 构建部署后检查真实页面。若运行环境阻塞部署，明确代码完成与已上线的区别，不虚报。

## 路线后的增量（不擅自纳入本轮）

- 平台特有的张数/大小上限适配，按实际页面提示增补；不宣称无限图片。
- 可选图片压缩/HEIC转换需用户选择质量策略，不默默降低原图品质。
- 固定公网入口、完整登录助手等保持独立待办，不因这轮视觉升级而宣称完成。
